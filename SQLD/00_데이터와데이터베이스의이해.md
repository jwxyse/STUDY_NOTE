# 0. 데이터와 데이터베이스의 이해

> ✏️ = 내 필기 · ⭐ = 시험 포인트

---

## 1. 데이터(Data)의 개념

- 현실에서 발생한 **사실이나 기록**
- 형태(숫자, 문자, 날짜, 사진, 영상 등)와 관계없이 어떤 현상을 기록한 것이면 모두 데이터

> ✏️ 음성도 포함

---

## 2. 데이터의 유형 ⭐

데이터는 표현 방식과 구조에 따라 세 가지로 나뉜다.

> ✏️ 데이터 유형에 따라 사용하는 DBMS가 달라짐

### 2-1. 정형 데이터 (Structured Data)
- 엑셀처럼 **행(row)과 열(column)** 로 구조가 명확하게 정해진 데이터
- 구조가 일정해서 검색·정렬·필터링이 빠름
- 예: 고객정보(고객번호, 이름, 연락처), 주문내역

> ✏️ 행과 열 = **2차원적 구조**
> ✏️ 주문내역 예시: 날짜, 품목, 수량

### 2-2. 비정형 데이터 (Unstructured Data)
- **정해진 구조가 없는** 데이터
- 표 형태가 아니라 컴퓨터가 바로 이해하기 어려움
- 예: 사진, 동영상, 음성 파일, 메신저 대화 내용

> ✏️ 사진을 분석해야 한다면 → 비정형 데이터를 **정형 데이터로 변환한 후** 분석

### 2-3. 반정형 데이터 (Semi-structured Data)
- **구조는 있지만**, 정형 데이터처럼 행과 열로 고정되어 있지 않은 데이터
- 웹 서비스, 모바일 앱에서 자주 쓰임
- 예: **HTML, XML, JSON**

```html
<!-- HTML -->
<p>이름: 홍길동</p>
```
```xml
<!-- XML -->
<Student><Name>홍길동</Name></Student>
```
```json
// JSON → key : value 형태
{ "name": "홍길동" }
```

> ✏️ 반정형 데이터는 **자기들끼리 규칙을 갖고 구조를 이루고 있음** (단, 행과 열 ✕)

---

## 3. DB와 DBMS의 차이

| 구분 | 의미 |
|---|---|
| **DB** (DataBase) | 데이터가 실제로 저장된 공간, 정리된 상태로 보관된 **데이터 그 자체** |
| **DBMS** (DataBase Management System) | 데이터베이스를 **생성·관리·제어하는 소프트웨어** |

- DBMS를 통해 데이터를 **검색, 삽입, 수정, 삭제**할 수 있음

> ✏️ DB = **데이터의 집합**

### DBMS가 필요한 이유
- 대규모 데이터의 빠른 조회
- 사용자 동시 접속 처리
- 데이터 무결성 보장
- 백업 및 복구
- 권한 관리

---

## 4. DBMS 종류

### 4-1. 관계형 데이터베이스 (RDBMS) ⭐
- **정형 데이터**를 저장하는 DBMS
- 데이터를 행과 열로 된 **테이블** 형태로 저장
- 예: Oracle, SQL Server, MySQL, PostgreSQL, MariaDB

> ✏️ RDBMS = **Relational** DataBase Management System = RDB
> ✏️ Oracle은 **유료**, MySQL·PostgreSQL·MariaDB는 **무료**
> ✏️ 관계형 DB → 엑셀 같은 정형 데이터

### 4-2. NoSQL
- 관계형 모델로 처리하기 어려운 **비정형·반정형 데이터**를 위한 DBMS
- 정해진 테이블 구조 없이 유연하게 저장
- 예: MongoDB, Redis, Cassandra, Neo4j

> ✏️ NoSQL → 사진, 영상, 음성 같은 비·반정형 데이터

---

## 5. SQLD 핵심 용어

### 5-1. 테이블 (Table) ⭐
- RDBMS에서 데이터를 저장하는 기본 단위
- **행과 열로 구성된 2차원 구조**

> ✏️ RDBMS = 정형 데이터 처리

### 5-2. 행 (Row) = 레코드 (Record)
- 테이블에서 **가로 방향**으로 저장된 데이터 단위
- RDBMS는 입력·출력·연산을 모두 행 단위로 처리

> ✏️ 행 = 레코드 = **인스턴스**

### 5-3. 열 (Column) = 속성 (Attribute)
- 테이블에서 **세로 방향**으로 정의된 데이터 항목
- 각 열이 테이블에 어떤 정보를 저장할지 결정 (예: 고객번호, 이름, 연락처, 가입날짜)

### 5-4. 스키마 (Schema) ⭐
- **테이블 구조를 정의한 설계 정보**
- 어떤 열이 있는지, **데이터 타입**은 무엇인지, **제약조건**은 어떤지를 모두 포함

> ✏️ 예시
>
> | 이름 | 참여 | 시간 |
> |---|---|---|
> | 홍길동 | 1M | 1H |
> | 김다임 | 2M | 2H |
>
> → 데이터 타입 & 제약조건 충족 = **스키마**

### 5-5. 기본키 (Primary Key, PK) ⭐⭐
- 각 행을 **유일하게 식별**하기 위한 한 개의 열 또는 여러 열의 조합
- 값 **중복 불가**, **NULL 불가** (NULL = 아직 정의되지 않은 값, 공백과 다름)
- **하나의 테이블에 하나만** 존재
- 예: 사번, 학번, 주문번호

> ✏️ 기본키 = **주식별자**
>
> ⭐ **PK는 한 테이블당 무조건 하나!**
> ⭐ **그러나 PK를 구성하는 컬럼은 두 개 이상 가능!**

#### ✏️ 식별자
- 테이블에서 각각의 행(데이터)을 구별할 수 있게 하는 속성
- ⭐ 식별자의 특징: **유일성, 최소성, 불변성, 존재성**

#### ✏️ 예시: 학생 테이블에서 식별자가 될 수 있는 것은?

| 학번 | 이름 | 주소 | tel | 주민번호 |
|:---:|:---:|:---:|:---:|:---:|
| O | ✕ | △ | △ | O |

- 이름 → **동명이인**이 있을 수 있어서 식별자 ✕
- 주소, tel → 식별은 가능하지만 **변경 가능성**이 있어서 최종적으로는 ✕
- ⭐ **주식별자는 하나만!**

### 5-6. 외래키 (Foreign Key, FK)
- 다른 테이블의 **기본키를 참조**하는 열, 두 테이블 간의 관계를 표현
- 예: 주문 테이블의 고객번호 → 고객 테이블의 고객번호를 참조

> ✏️ **부모-자식** 간의 관계를 갖고 있음

### 5-7. 데이터 타입 (Data Type)
- 엑셀과 달리 테이블의 각 컬럼은 정해진 데이터 타입을 가짐
- **숫자형(Number), 문자형(Char, Varchar2), 날짜형(Date)**

### 5-8. 제약조건 (Constraint)
- 데이터의 **정확성과 무결성**을 보장하기 위해 입력을 제한하는 규칙

> ✏️ 컬럼마다 만드는 제약 장치

| 구분 | 설명 |
|---|---|
| PRIMARY KEY | 각 행을 유일하게 식별 (중복 불가, NULL 불가) |
| UNIQUE | 중복 값 금지 |
| CHECK | 특정 조건만 허용 |
| FOREIGN KEY | 다른 테이블의 데이터를 참조 |
| NOT NULL | 빈 값 입력·수정 불가 |

> ✏️ CHECK 예시: 급여 테이블이면 `sal > 0`
> ✏️ NULL은 "0"이 아니라 **"미정"** 이라는 뜻

### 5-9. 관계 (Relationship)
- **테이블 간의 연결**
- RDBMS의 핵심: 모든 테이블은 최소 하나 이상의 다른 테이블과 관계를 맺음

### 5-10. 뷰 (View)
- 실제 데이터를 저장하지 않고, 기존 테이블의 원하는 부분만 **가상의 테이블처럼** 보여주는 객체

> ✏️ 실제 데이터(테이블)가 아닌, 미리보기 형식으로 비슷한 테이블을 만들어 보여줌 (= **보안 장치**)
> ✏️ 객체 = 만들 수 있는 대상 (예: 테이블, 인덱스, 제약조건, 뷰)

### 5-11. 인덱스 (Index)
- **검색 속도를 높이기** 위한 자료구조(객체)

> ✏️ 예: 책의 목차

### 5-12. 트랜잭션 (Transaction) ⭐
- 데이터베이스에서 **하나의 작업 단위**
- **모두 성공하거나 모두 실패**해야 함 (All-or-Nothing)
- 예: A → B 계좌이체 시 A -10만 원, B +10만 원이 함께 성공해야 함

> ✏️ 트랜잭션 = **묶여 있는 업무 단위**

### 5-13. SQL (Structured Query Language)
- RDBMS에서 데이터를 **정의, 조작, 제어**하기 위한 표준 언어
- SQL 문장은 명령의 끝을 구분하기 위해 **세미콜론(;)** 으로 마무리

> ✏️ Structured = 구조화된, Query = 질의
> ✏️ 쿼리(Query) = SQL로 데이터베이스에 요청하는 문장 → 쿼리는 무조건 `;`로 마무리

---

## ⭐ 시험 포인트 정리

1. **데이터 유형** 3가지: 정형(행·열) / 비정형(구조 없음) / 반정형(구조 있음, 행·열 ✕ — HTML, XML, JSON)
2. **RDBMS**는 정형 데이터, **NoSQL**은 비정형·반정형 데이터
3. **테이블** = 행과 열로 구성된 2차원 구조
4. **스키마** = 테이블 구조를 정의한 설계 정보 (열, 데이터 타입, 제약조건)
5. **기본키(PK)**: 중복 ✕, NULL ✕, **테이블당 하나**, 단 **구성 컬럼은 여러 개 가능**
6. **식별자 특징**: 유일성, 최소성, 불변성, 존재성 / 주식별자는 하나만
7. **트랜잭션** = 하나의 작업 단위, All-or-Nothing
